BOUNDED AGENT CLOSURE · FROZEN ENGINE · 8 BOUNDARY CASES

Agent Closure Inspector

Stopping an autonomous agent from creating new work does not tell you whether the consequences it already created are finished.

This instrument follows the consequences still attributable to a retiring agent, applies the terminal condition each consequence actually requires, and shows whether the available evidence supports bounded closure, exposes a known blocker, or leaves the answer unresolved.

What the verdict means
CLOSED

Every in-scope attributable consequence satisfies its declared terminal disposition with sufficient coverage, freshness, stability, and final confirmation.

INCOMPLETE

A known consequence or unstable final state still prevents closure. The blocker is identified rather than hidden behind a generic failure.

UNKNOWN

The evidence surface is not strong enough to establish closure. Missing visibility is kept separate from a known live blocker.

01

Block new authority

Retirement begins after the root can no longer initiate new business. That is a starting premise, not the closure verdict.

02

Follow consequences

Traverse evidence-backed DERIVED_FROM lineage so a descendant job or commitment does not disappear behind an already-quiet parent.

03

Apply the right ending

Extinguish, settle, transfer, and retain are different terminal dispositions. Closure does not mean deleting everything.

04

Confirm stability

Coverage, attribution, fresh observation, source stability, and final-pair semantic convergence are required before CLOSED.

Four useful contrasts

The cases are designed to break simple closure rules.

The corpus is most useful when read as a set of opposing examples. A success response can still fail. A surviving object can still be terminal. A clean graph can still be unknown. One clean scan can still be too early.

C7 · False Success

Success is not the postcondition.

A cancel operation reports success while the schedule remains present, active, and linked to the retiring root.

C5 · Successor Transfer

Survival is not necessarily failure.

An active object can be closed relative to the old root when responsibility has moved to an accepted successor.

C6 · Missing Coverage

Silence is not evidence of closure.

No known blocker appears, but a required source cannot establish complete coverage.

C8 · Fixed-Point Wind-Down

Clean once is not stable.

A later retry enters the consequence cone, so closure waits until the terminal semantic state is confirmed again.
