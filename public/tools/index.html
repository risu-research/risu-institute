A tool can look the same while changing what the action can do.

RISU Verify asks whether the distinctions that determine a declared consequence remain represented, distinguishable, and operative at the effect cut.

The current release combines proof-carrying verification, retained GitHub and Azure cases, one real historical GitHub regression-to-repair transition, audit-hardened provenance, a development Version-Bound Effect profile, and a prospectively sealed Corpus 0.1 protocol. The browser Workbench does not issue new assurance certificates; it independently recomputes report-level status mapping, world matches, SHA-256 file digests, and cross-artifact commitments.

Canonical mode renders retained v0.4.0-rc1 calibration data. It does not rerun the Python producer or independent proof checker in the browser. The GitHub historical transition is retrospective validation against independently developed software, not an independent bug-discovery claim.

Inspect a real RISU result.

Load report.json. Add certificate.json and run-manifest.json for stronger cryptographic and cross-artifact checks. You may also add report.md, logs, case.json, adapter.json, or source-contract.json to verify their recorded manifest digests.

Browser checks are deliberately narrower than a RISU assurance run. They recompute product-status mapping, world-level matches, selected certificate/report commitments, and SHA-256 bindings for files you provide. They do not verify provenance facts, source-model completeness, or the proof-carrying certificate itself, and they do not issue a new RISU verdict.
