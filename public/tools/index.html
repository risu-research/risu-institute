Flagship research software · v0.4.0-rc1

Same tool.
Different consequence.

An AI-facing tool can keep the same name and inputs while losing a safeguard that changes what the action actually does. RISU Verify checks whether that safeguard survived.

You do not need to understand formal methods to use the idea: say what must happen, examine the projected action, then check whether every allowed situation still leads to the right consequence.

Why this exists

Interfaces can preserve appearance while changing meaning.

1 · Reviewed sourceA consequence is declared.

Example: update only the version that was actually reviewed. If the underlying version changed, reject the stale action.

→
2 · Agent-facing projectionThe action is exposed through another interface.

The tool name, schema, and visible inputs can still look correct even if the decisive safeguard is weakened, misplaced, or lost.

→
3 · RISU VerifyCheck consequences, not appearances.

RISU compares the declared source consequence with what the projected action produces across bounded admitted situations.

Why it matters: an agent can act through a tool that appears unchanged while the action no longer respects the condition a human, policy, or upstream system relied on.

What you get

A small set of answers with explicit boundaries.

✓

Safeguard preserved

The declared consequence is realized and the material distinction still governs the effect within the stated scope.

×

Safeguard lost

At least one admitted situation reaches the wrong consequence, or the necessary distinction does not govern the consequential effect.

?

Not enough assurance

The current evidence or declared model does not justify either a preservation result or a contradiction.

Evidence and reproducibility

The simple story is backed by inspectable artifacts.

The current release retains GitHub and Azure calibration cases, a real historical GitHub regression-to-repair transition, audit-hardened provenance, a development Version-Bound Effect profile, and a prospectively sealed Corpus 0.1 protocol.

The historical transition is retrospective validation, not an independent bug-discovery claim. The VBE profile is calibrated on retained cases; prospective generalization is reserved for Corpus 0.1. RISU Verify provides bounded, model-relative assurance rather than whole-system safety.

Drop the output from a RISU Verify run. The Workbench independently recalculates the report-level status, checks each bounded-world consequence, computes file SHA-256 digests, and cross-checks certificate and run-manifest commitments when you provide them.
